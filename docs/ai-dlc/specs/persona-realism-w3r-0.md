# W3R-0 — Arrival-range Fold-to-Bet measurement harness (measurement-first)

**Slice of:** `docs/ai-dlc/roadmap/persona-realism.md` → W3R (bot-review remediation). FIRST slice of the wave
(owner chose measurement-harness-first / hard-prove dials). Prereq for W3R-2 (fish/station dial fits).

## Goal (one line)
Add a per-persona **arrival-range** fold-to-bet-by-size measurement harness — the hands each bot realistically
reaches each street with, generated by **replaying its own preflop (and street) policy**, not a uniform deck —
across **flop / turn / river**, plus documented target bands wired as **xfail/skip until W3R-2**. **Measurement
only: ZERO bot behavior change.**

## Why (the gap)
The existing `fold_by_size` fixture (`tests/test_personas_postflop.py:455`) measures fold-to-bet over a UNIFORM
random deck — air-heavy, so it can only prove **slope/direction**, never the archetype **absolute bands** (station
overbet 18–40%, fish 60–80%). Those §5 keystone magnitudes are gated NOWHERE. W3R-2 (station `size_elasticity`
0→~0.55, fish `call_looseness` ~0.95) needs a harness that measures fold-rate over each persona's realistic
arrival range to be hard-provable rather than directional.

## Owner decisions (2026-07-24 interview)
1. **Arrival range = replay the real preflop policy** (`sample_preflop_action`) — deal hands, run the bot's own
   preflop code for a canonical setup, keep the hands it continues with; that kept set IS its arrival range.
   Faithful, reuses existing code, no solver. **(refuter HIGH fix)** For the fold-to-c-bet node the bot is the
   **caller/defender**, so its arrival range is **CALL-ONLY** — the hands it flat-calls an RFI with (`vs_rfi`
   `call` action). **3bet/raise hands are EXCLUDED**: a 3bettor is the aggressor and would be c-BETTING, not
   facing a c-bet, so counting them pollutes a single-raised-pot arrival range and shifts the very bands we gate.
2. **Scope = all streets (flop, turn, river).** Flop bands are HARD (grounded); **turn/river are measurement-only**
   (no grounded absolute bands yet → emit curves, no hard assertion).
3. **Band checks land xfail/skip until W3R-2** — the harness + bands land GREEN today with no behavior change;
   W3R-2 flips them live when the dials are fit.

## Canonical measurement setup
- **Reference pool:** online low-mid 9-max ~100bb (the initiative keystone — do not change).
- **Flop:** heads-up single-raised pot. **Role is load-bearing (refuter MED fix):** the **villain is the RFI
  raiser** and the **bot is the `vs_rfi` caller/defender** facing the c-bet at {0.33, 0.5, 1.0, 1.5}× pot (mirror
  `PRICE_FRACS`). Arrival range = the persona's `vs_rfi` **CALL** hands ONLY (3bet hands excluded — see decision 1).
  `sample_preflop_action(pack, position, facing, hole_cards, rng)` is called with `facing="vs_rfi"`; all packs'
  `vs_rfi` nodes are `positions=None` (wildcard) so position is a no-op, but `facing` + the caller role are fixed.
- **Turn/river:** the bot's continuing range into that street (hands it kept betting/calling on the prior street),
  facing a bet at the same size buckets. **This is the heavy part** — it requires simulating the persona's
  continuation forward (which hands reach the turn/river), so the T3 ticket may sub-split at build time.
- Seed-pinned + paired (same dealt spots across persona×size), like the existing fixture, so variance cancels.
