# Blind review, round 1: M2 spec (retune the LAG at 6-max, plus the board-straight fix)

## Bottom line
- **Verdict: fail.** The spec cannot pass as written, but each fix is cheap and none needs code outside the spec's own file list.
- **The blocker:** the 9-max check that each changed hand is caused by the bug fix fails by construction. The 9-max harness shares one random-number stream across hands. In the test, one genuinely changed hand (hand 275) shifted every later hand, and in 84 hands the first difference was a pre-flop action. The spec's own fallback ("stop and report") would therefore trigger every time.
- **The same shared stream undermines two other measurements.** The 6-max "commit 1 to commit 2 is the fix's share" comparison is mostly sampling noise. The median-raise-size check already passes before any change (3.00×), so it cannot fail and does not measure the 5× raises the owner complained about.
- **Two predictable outcomes are left for after the build:**
  - the target opening ranges project LAG PFR (pre-flop raise rate) to about 19.4%, just under the 20% floor;
  - the LAG would open fewer hands than the unchanged TAG from the two earliest seats. That blurs the types, and the roadmap's separation guard forbids blurring them, yet the spec never mentions the guard.
- **Holding up:** the board-made-hand rule itself and its must-stay-MONSTER cases, the override merge assumptions, the computability of the raise multiple, the `rr_emit` emission, and the drift-gate extension.

## How this was checked
- **Method:** read-only, against the worktree at `e62892b`. The fix was simulated by patching `_made_bucket` in memory, never on disk, with the spec's literal rule: `cat >= 4`, five board cards, and `_best5(hole+board) == _best5(board)` returns MIDDLE_PAIR.
- **Tests run with the patch:** nine backend test modules. The result was 552 passed and 3 failed, all of them pins the spec already plans to re-pin: both golden digests and `test_persona_stats_byte_identical_after_log_refactor` (the `_GOLDEN_STATS_N200` pin). `BANDS`, the range-estimate tests and the post-flop context tests stayed green.
- **Not run:** `make check`. There is no code diff to gate; this is a spec review.
- **Simulations:** `run_baseline` was run with 6,000 hands at seed 20260926, plus seeds 1–5 for the small-blind (SB) check. All dial trials were in-memory `model_copy` patches.

## Claims verified and holding
- **The rule (§4):** all four MIDDLE_PAIR cases flip, and all three must-stay-MONSTER cases hold. A demoted hand cannot become a busted-draw river bluff, because that path requires AIR or ACE_HIGH (`postflop_context.py:229-230`). It also cannot trigger the low-SPR commit (low stack-to-pot ratio), because that requires OVERPAIR_TPTK or better (`personas_postflop.py:1887`). There is no second classifier with the same bug: `_best5` and `_made_bucket` have one production caller chain (grep).
- **Override merge:** `postflop.sizing` is replaced whole, and `continue_ref` is a plain key (`personas.py:98-104`). The `unopened` override replaces all base nodes of that facing (`personas.py:94-97`).
- **Raise multiple:** it is computable from replay rows as `(street_inv_before + amount) / (street_inv_before + to_call)`. The station example gives 9.45 / 1.98 = 4.77×.
- **`rr_emit` and the drift gate:** `emit_nodes` round-trips every node through `PersonaNode`. The override's `preflop["unopened"]` can be compared exactly as the base gate does (`test_rr_emit.py:319-361`).
- **Feasibility of the dials:** `continue_ref` 2.0 with flat sizing {0.33: 0.45, 0.5: 0.35, 0.75: 0.10, 1.0: 0.10} gives a raise-when-bet-into rate of 16.4% (14.2–18.9%), a median of 2.66×, and passes every size-ecology and pack-invariant test at 6-max (50 passed, in-memory).
