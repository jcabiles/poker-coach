## Findings

**1. should-fix — `/tmp/claude-501/wt-rd/frontend/src/components/SimulateView.tsx:1103-1113`. Moving focus to `div.sim-review` (tabIndex={-1}) arms Space/Enter to deal the next hand.**
The global deal-key handler is live under exactly the spec's gate (`hand_over && revealHandEnd && !replay && !checkPending`, line 1102) and skips only `button, a, input, textarea, select, [role="button"], [contenteditable="true"]`. A `div` with `tabIndex={-1}` matches none of them. So: tap "Review ↓" (or press Enter on it) → focus lands on the wrapper → the user presses **Space to scroll the recap they just navigated to** → `e.preventDefault(); nextHand()` fires and the review is destroyed. This is a regression the spec creates, not a pre-existing one. Same hazard for the spec's `h1` focus fallback in §3, which also runs with `replay === null`.
Fix: add the wrapper (and the two `h1` fallbacks) to the `closest()` skip list at line 1108 — e.g. `, .sim-review, [tabindex="-1"]` — and say so in §1/§3.

**2. should-fix — spec §"Constraints", line 161-163. The claimed focus-ring default does not exist.**
The spec says "`outline: none` on `:focus:not(:focus-visible)` is already the app's default; verify, do not add." Grep finds no such rule. The only global is `frontend/src/styles/tokens.css:244` — `:focus-visible { outline: 3px solid var(--primary); outline-offset: 2px }`. The repo's actual convention is a **per-element opt-out**: `app.css:6047` `.smc-title[tabindex="-1"]:focus{outline:none}`, `:6155` `.sbc[...]`, `:6644` `.sbc-score[...]`. Chrome matches `:focus-visible` on a scripted focus when the last input was a keypress, so pressing Enter on "Review ↓" paints a 3px gold ring with 2px offset **around the entire ~1,052px showdown+recap wrapper**. Following the spec literally ("do not add") ships that.
Fix: state the real rule, and have §1 add `.sim-review[tabindex="-1"]:focus { outline: none }` (and decide explicitly for `.hr-title`/`.hrt-title`/`.history-title`/the Simulate `h1`, where a ring on a heading is arguably wanted).

**3. should-fix — spec §3 Esc, vs `/tmp/claude-501/wt-rd/frontend/src/App.tsx:297-307`. One Escape closes two things.**
The rail sheet binds its own `window` `keydown` while `sectionsOpen` and does not `preventDefault`. The sheet is the phone's nav and is reachable from both replayers. With a window-level Escape added to `HandReplay.tsx:114-132` / `HandReplayTable.tsx:119-141`, one Esc dismisses the sheet **and** closes the replayer underneath it — on History that discards a place in a 126,448px list, which is the exact defect this slice exists to fix. The blind-check `<dialog>` (`SimulateView.tsx:1659`, rendered outside the `replay ?` branch) is a narrower second instance: its `keydown` bubbles to `window` too.
Fix (in scope, no `App.tsx` edit needed): guard the replayers' Escape case with `if (document.querySelector(".nav-tabs-open, dialog[open]")) return;` — `App.tsx:399` already puts `nav-tabs-open` on the sheet. Add it to the spec's stated guards beside "no modifier keys, not inside an editable element".

**4. should-fix — spec §3 and Verify-by leg (b). `focus()` undoes the restored scroll.**
The spec's order is "restores `window.scrollTo(0, savedY)` **and** focuses the row button". `HTMLElement.focus()` scrolls its target into view, and under the phone gate `html { scroll-padding-bottom: calc(var(--space-8) * 4) }` (`app.css:6755`, 128px) makes "in view" mean "not in the bottom 128px". A row tapped in the lower third of the screen — the common case — will be scrolled by up to 128px right after the restore, so leg (b)'s "`window.scrollY` to within 1px of the saved value" cannot hold. Same for `.sim-replay-btn` in Simulate, and for the mount-time `h2` focus in §2.
Fix: specify `el.focus({ preventScroll: true })` at every focus move in §1/§2/§3.

**5. should-fix — spec §2 defeats spec §4 on the History replayer.**
§4 renders the rotate hint as the **first child of `section.history`**, i.e. above `section.hrt.history-replay` (`HandReplayTable.tsx:144`). §2 then scrolls that section to viewport top on mount. At 360×800 the document with a replay open is 1,561px (measurement §3a) and the replayer starts at doc y383, so `scrollIntoView({block:"start"})` sets `scrollY ≈ 383+hint` and puts the hint entirely above the fold. The one screen where the hint exists is the one screen it is scrolled off. Verify leg (d) would still "pass" if the reviewer scrolls up first.
Fix: pick one — render the hint inside the replayer section above `.hrt-head`, or give the scroll target a `scroll-margin-top` large enough to keep the hint visible, and say which in §2.

**6. should-fix — spec §5. `.sim-review-btn` in the floor list is dead CSS, and the measurement list is short one number.**
`.decision-btn` already carries `min-height: calc(var(--space-8) + var(--space-3))` at `app.css:626` — the identical 44px floor. The new button has `className="btn decision-btn sim-review-btn"`, so it is already ≥44px; adding `.sim-review-btn` to the gate list at `app.css:7036-7043` changes nothing. Relatedly, §5 names seven selectors but gives six measurements ("93×24, 63×32, 71×39, 104×42, 104×42, 24px rows") — the seventh cannot have been measured because it does not exist yet.
Fix: drop `.sim-review-btn` from §5 (keep it in Verify-by leg (e) as a check), and note in §1 that the floor comes free from `.decision-btn`.

**7. optional — stale line references throughout the spec.** `app.css:7039-7046` is actually **7036-7043**; `SimulateView.tsx:1458-1470` (rotate hint) is **1458-1477**; `SimulateView.tsx:1589-1608` (review fragment) is **1589-1607**. §5 also asserts the gate wins over "`min-height: 32px` at `app.css:5414`" — line 5414 is `.hr-step-btn { min-height: calc(var(--space-8) + var(--space-2)) }`, i.e. 40px, not 32px. **8. optional — `closeReplay` is also the error-dismiss handler in both views.** `HistoryView.tsx:218` and `SimulateView.tsx:1352` call `closeReplay` from the "Dismiss" link on a replay-*load* failure, when `replay` is already `null`. The spec has `closeReplay` set the restore-pending ref, so that path leaves a ref set that no effect consumes (deps `[replay]` do not change), to be fired on some later close. Harmless today because `openHand`/`openLastReplay` re-record `savedY`, but it is a latent stale-restore. Fix: set the pending ref only when `replay != null` at call time, or clear it in the open path.
