## NOTES

**(i) Field count.** 21 genuinely per-persona-authored fields/sub-fields (rows 2–21).
Numeric-sweepable: rows 2, 3, 4, 10, 11, 12, 13, 14, 15, 16, 17, 18 (weights), 19 (weights),
20, 21 — **15 numeric axes**, several mutually exclusive fallback pairs (11↔12, 11↔13)
rather than independent. Structural-only: rows 1, 5, 6, 7, 8, 9 (key sets), 18/19 (key
sets), 22.

**(ii) Frozen/immutable set.** `continue_ref` (row 14 — key-presence validator; runtime
division-site guard because `model_copy(update=...)` bypasses pydantic); `_LINE_DELTA=1.0`
(code constant, units pin); node ordering / role-tagging laws (rows 5–7, enforced by
`PersonaPack._node_ordering`); the `_FACING_ACTIONS` action-vocabulary map.

**(iii) Flagged unknowns (not guessed).** `sizing_by_node`'s `"flat"` key may be dead
(engine may never look it up when `is_aggressor=False`) — no shipped pack authors it;
needs a targeted trace before the contract declares it sweepable. Full `positions`/`role`
coverage for `calling_station.json`/`passive_fish.json` not read line-by-line. The numeric
mapping between `size_elasticity` scale and the legacy `stickiness`-derived exponent is not
1:1 and was not derived.

**(iv) Preflop mix table ordering semantics.** Two nested first-match-wins scans, both
pinned: node selection scans `pack.preflop` in list order (facing + positions + role
match); mix selection scans `node.mixes` in list order (first `combos` match wins; no
fallthrough — an uncovered hand class is an unconditional fold; unassigned weight mass is
an IMPLICIT FOLD). Node insertion order and mix insertion order are both semantically
load-bearing — reordering entries changes behavior even with identical weights.
