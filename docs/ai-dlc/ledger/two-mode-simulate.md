`refuter` (Opus, high effort) and Codex `gpt-5.6-sol`. **Both returned REJECT.** Raw reports:
`../reviews/two-mode-simulate-r1-claude.md`, `../reviews/two-mode-simulate-r1-sol.md`.

Every finding below was checked against the code before it was accepted. Reviewer output is a
report, not a verdict.

## Process failure worth recording

The first two Codex invocations produced nothing usable and the first one was actively
misleading. `CODEX-REVIEW.md` §5 prescribes `CODEX_HOME="$HOME/.codex-ai-org"`, a **fixed shared
path**. That directory is outside this repo's sandbox write allowlist, so `mkdir`/`cp` were
denied — but the directory already existed, created by a concurrent Claude session reviewing a
different repository. Codex ran against that session's state and returned a review of
`purposeful-youtube-feed` (Node/Fastify/better-sqlite3) into an empty report file. The second
attempt used a unique home under the same denied parent and died at `mkdir`. Only the third,
with `CODEX_HOME="$HOME/.codex/ai-org-2mode"` (inside the writable `~/.codex`) and `--cd` pinned
to the repo root, reviewed this repository. The log header was checked for `workdir:` before a
word of its findings was read.

**Gain of fixing the shared recipe: reviews stop silently reviewing the wrong repo. Cost: one
line changed in a reference file.** Not done here — it is outside this slice.

## Carried forward — not fixed, deliberately

- **The live-hand branch of `deal_next_hand()` has the same unguarded stored-state read** that finding B9 fixed one branch below it. It predates this slice, and fixing it changes behaviour outside any current ticket's acceptance criteria. The gain of leaving it is a diff a reviewer can bound to the gate; the cost is that the underlying defect survives in the adjacent branch.
- **`backend/app/services/sim_session.py` is 1801 lines**, well past the repository's roughly 500-line guidance, and T4 adds the seat pick, scoring and submission to the same file. Flagged rather than grown silently, per the engineering standard. The Director ruled T4 stays in that file: the ticket is owner-approved and names it, T4's additions are tightly coupled to session helpers already there, and restructuring mid-chain would break the one-file-one-owner discipline the whole plan rests on. The proposed split — a separate blind-check service module — gains a file under the guidance and costs one more import in the API layer, and should be done as its own change after the slice lands.
- **No route-level test exercises the barrier through the HTTP layer.** The barred branch returns the same response model as every other branch, so the contract is unchanged and the risk is low. Recorded so the omission is a decision rather than an oversight.
- **A test that passes against broken code is worse than no test, and one nearly shipped as evidence.** T4's first concurrency reproduction asserted on a row re-fetched from the database session rather than one held in a local variable. SQLAlchemy's identity map holds **weak references**, so the row was collected, the second caller silently re-read after the first had committed, and the test passed against the unfixed code. The worker caught it themselves and rewrote the test to hold both rows for the length of the block — and, better, to **check its own reproduction**, asserting the second caller is genuinely stale before it submits, so a future library change makes the test fail loudly instead of passing while testing nothing.
- **One deliberately unreachable branch** sits at the end of the blind-check submission: if the losing side of the race cannot read the winner's stored value, it raises rather than returning its own unstored score. Only that function writes the column and only ever writes a serialised view, so the state is not reachable today. It is kept because both alternatives are worse — reporting a result that was never stored is a lie to the caller, and re-entering the function is unbounded recursion.
